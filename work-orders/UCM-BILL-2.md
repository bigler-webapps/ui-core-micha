# UCM-BILL-2 — Operator surfaces for billing and a richer „Abo" section

## Part A — Envelope (everyone)

**Tier:** 3 — screens showing billing data of all accounts to the operator and a switch that grants
access. **Repository:** `bigler-webapps/ui-core-micha`. **Canonical:** DCM-BILL-5 (django-core-micha);
starts after its API is fixed. Builds on UCM-BILL-1 (`SubscriptionSection`) and the shared Users tab.

### Goal and expected outcome

The operator wants to see per app how the subscriptions and AI costs develop and to grant or revoke
free access without a command line; people want to see in „Abo" what they have: plan, term, token
grants with expiry and, as team payer, who holds a seat.

Expected outcome: an operator overview, an access column with switch in the shared Users tab, and a
more complete „Abo" section — all from DCM-BILL-5, nothing computed in the browser.

### Settled decisions (operator, 2026-10-16/17)

1. **Operator overview** (a component the app places in its operator area): month selector; cards
   for active accounts by source (Abo per plan, Team-Platz, Ohne Abo freigeschaltet), new and ended
   subscriptions, packages sold, tokens granted / used / expired, AI cost in USD with cost per used
   token; a small table AI cost by provider and model. Read-only.
2. **Shared Users tab:** a column „Zugang" (Abo {Plan} bis {Datum} · Team-Platz · Ohne Abo
   freigeschaltet · Schreibgeschützt) and per account the switch „Ohne Abo freigeschaltet"; switching
   on asks for a mandatory reason („Grund"), switching off asks for confirmation and states that the
   data stays and becomes read-only if no other access exists. Only shown to operators and only when
   the app has billing.
3. **„Abo" section** (extends `SubscriptionSection`): plan name and billing period, term end and
   whether it renews or ends; token grants as a list (Kontingent / Paket, Betrag, verbleibend, gültig
   bis); for a team payer the seats („{n} von {m} Plätzen belegt") with the holders' names and the
   existing seat assignment; a seat holder sees „Team-Platz bis {Datum}".
4. Plain words, no Stripe terminology; DE, EN, FR (and the existing de_informal/sw where the kit
   carries them).
5. No own prototype; the surfaces follow the account-page and Users-tab patterns of the kit.

### Scope and acceptance

Components and wiring against DCM-BILL-5, catalogue entries, i18n, tests; existing tests of
UCM-BILL-1 stay green.

### Non-goals and do-not-touch

Changing subscriptions or refunds (Stripe), cross-app finance (bigler-consult), deletion.

### Risks

Showing operator data to a non-operator would expose all customers; the components render only on
explicit operator data from the server, and a 403 shows nothing.

### Required tests to write or update

Overview with seeded data and empty month; Users-tab column and switch (grant needs reason, revoke
confirmation, error states); hidden without operator permission or without billing; „Abo" section
for personal subscription, team payer with holders, seat holder, free access, read-only; i18n
completeness.

### Backend contract (django-core-micha 3.7.0, DCM-BILL-5; isolate every name in `src/billing/wire.js`)

Base `apiBase` default `/api/billing/`. Errors carry `{ detail: <code> }` (NOT `code`): anonymous 401 `authentication_required`, a non-operator 403 `forbidden`, bad month 400 `invalid_month`, bad paging 400 `invalid_page`, long query 400 `invalid_query`, missing reason 400 `reason_required`, unknown user 404 `user_not_found`. Read the code from `error.response.data.detail`. CSRF on POST and DELETE is handled by the shared `apiClient` (`src/auth/apiClient.jsx`, as in `src/billing/api.js`).
- `GET operator/overview/?month=YYYY-MM` (month optional; default the current UTC month) -> `{ app, month, accounts: { active, by_source: { subscription: { <plan_key>: n }, team_seat: n, free_access: n } }, subscriptions: { new, ended }, team: { packages_active, packages_sold, seats_total, seats_used }, token_packages: { sold, tokens }, tokens: { granted, used, expired }, ai_cost: { calls, usd_micros, by_model: [ { provider, model, calls, usd_micros, input_tokens, output_tokens, cache_tokens } ], usd_micros_per_used_token: n | null } }`. All numbers are integers; `usd_micros` is millionths of a US dollar. Aggregates only.
- `GET operator/accounts/?q=&page=&page_size=` (page from 1, page_size at most 100) -> `{ count, page, page_size, results: [ { user_id, email, name, access: { status: 'active'|'read_only', source: 'free'|'subscription'|'team'|null, ends_at }, plan_key: string|null, term_ends_at: ISO|null, token_balance, free_access: null | { reason, granted_by, granted_at } } ] }`.
- `POST operator/accounts/<user_id>/free-access/` body `{ reason }` (1 to 1000 characters; 201 created or 200 if already active) and `DELETE` on the same path (200 `{ revoked: boolean }`). Both answer `{ user_id, free_access: null | {...}, access: { status, source, ends_at } }`.
- `me/` additions (existing keys unchanged; every new key is optional, render it only when it has the shape below): `subscription: null | { plan_key, plan_name, status, current_period_start, current_period_end, renews: boolean, cancel_at_period_end: boolean }`; `tokens.grants: [ { source: 'plan'|'package', amount, remaining, expires_at: ISO|null } ]` (soonest expiry first); `team: null | { plan_key, plan_name, ends_at, seats_total, seats_used, seat_holders: [ { user_id, name, email } ] }` (payer only); `seat: { plan_key, plan_name, ends_at }` (a person who holds a seat; never other holders). `plan_name` may be `""` (show `plan_key`).

2. `useOperatorAccounts.js`: `useOperatorAccounts(api, { enabled = true } = {})` -> `{ status: 'idle'|'loading'|'ready'|'hidden'|'error', accounts: Map<number, account>, reload, setFreeAccess(userId, answer) }`. When enabled it loads the pages of `listOperatorAccounts({ page, pageSize: 100 })` one after another until `count` is reached (at most 50 pages), ignoring results after unmount or when `api` changes (a generation counter, as in `src/receipts/useReceiptConsent.js`). A 401, 403 or 404 on the FIRST page (or any page) means `hidden` and the accounts are dropped (no operator right, or the app has no billing); any other failure is `error`. `setFreeAccess` merges the answer of a grant or revoke (`free_access`, `access`) into the account.
3. `FreeAccessSwitch.jsx`: props `account`, `api`, `onChanged(answer)`, `sx`. An MUI `FormControlLabel` + `Switch` labelled "Ohne Abo freigeschaltet" (accessible name). Switching ON opens a `Dialog` with a required multiline text field "Grund" (1 to 1000 characters; the confirm button "Freischalten" stays disabled while the trimmed text is empty or over 1000), cancel "Abbrechen"; confirm calls `api.grantFreeAccess(account.user_id, reason.trim())` once (guard against a double click), then `onChanged(answer)` and close. Switching OFF opens a confirmation `Dialog` titled "Freischaltung aufheben?" with the body "Die Daten bleiben erhalten; ohne anderen Zugang sind sie danach schreibgeschützt." and the buttons "Abbrechen" and "Aufheben"; confirm calls `api.revokeFreeAccess(account.user_id)`. While a request runs the controls are disabled; a failure keeps the dialog open and shows an `Alert` (`Billing.OP_SAVE_ERROR`; a 403 shows `Billing.OP_FORBIDDEN`); the switch never shows a state the server did not confirm (it reflects `account.free_access`, which changes only through `onChanged`).
4. `BillingAccessCell.jsx`: props `account`, `api`, `onChanged`. Below it the `FreeAccessSwitch`. Dates through `formatDate`.
